# P5 · 제출 감사

**언제:** T+255~285. 이 시점부터 기능 추가 금지.
**사람:** `~/finals/checklists/grading_2h.md`를 열고 에이전트 보고와 대조한다. 플랫폼 제출 방식·용량 제한을 다시 확인한다.

```text
기능 추가를 멈추고 제출 감사를 해라. 최소 수정만 허용한다.
1) §2 필수 산출물이 정확한 경로·파일명·형식으로 존재하는지 확인한다. sample 출력이 있으면 컬럼·순서·타입·행 수를 diff로 비교한다.
2) 깨끗한 상태에서 재현한다: 결과물 과제는 과제 폴더를 임시 위치에 복사해 §2 한 줄 실행 명령을 처음부터 돌리고 같은 결과가 나오는지 확인한다. 웹 과제는 cd web && pnpm build 와 bash scripts/smoke.sh, 그리고 bash scripts/check-placeholders.sh 가 0건인지 확인한다.
3) `bash verify_full.sh`(빌드·깨끗한 재현 포함)를 실행하고 §7 각 AC를 통과/실패/미검증으로 사실대로 표시한다. 실패를 통과로 바꾸지 않는다.
4) §8 금지 행위 위반이 없는지 확인한다: git 쓰기 명령 흔적, 원본 데이터 변경(`/tmp/orig.sha`가 있으면 `shasum -c /tmp/orig.sha`로 대조, 없으면 mtime), 외부 전송, 하드코딩된 데이터 값, 절대경로, 대화형 입력.
5) 엣지 입력(빈 파일, 결측 컬럼, 미지 ID)에서 명시적 오류로 끝나는지 1회씩 확인한다. 실행 시간을 측정해 §2에 적는다.
6) SUBMISSION에 들어갈 "증거표" 초안을 만든다: §7 AC마다 한 줄, 주장 → 확인 명령 → 실제 출력(또는 파일 경로). 심사자가 README만 읽어도 검증할 수 있게.
7) 결과를 §0 상태판과 DECISIONS.md("HH:MM | 감사 | 통과 n/실패 m/미검증 k")에 남기고, 실패·미검증 항목과 그 이유를 보고해라.
```
