# P2 · AC1 수직 흐름

**언제:** T+25~90. 게이트: 제출 파일이 산출물인 과제(예측 파일·ETL)는 **T+45에 형식이 맞는 baseline 제출 파일**(예측은 평균·다수 클래스, ETL은 원천 1개 변환 결과)이 있어야 하고, 그 밖의 과제는 T+90에 AC1이 통과해야 한다. 안 되면 범위를 줄여서라도 통과시킨다.
**사람:** 첫 결과가 나오면 직접 실행하거나 화면을 열어 확인한다. 웹이면 서버는 Terminal 3에 하나만.

```text
먼저 과제 루트의 AGENTS.md를 읽어라. CONTRACT §7의 AC1만 끝까지 구현해라. §2 산출물이 제출 파일인 과제(예측 파일·ETL)면 3)에서 형식이 맞는 baseline 제출 파일(예측은 평균·다수 클래스, ETL은 원천 1개 변환 결과)을 가장 먼저 만들어 형식 검사를 통과시킨 뒤 나머지를 한다. 참고 문서는 §10에 적힌 shape 파일(주 shape, 있으면 계산 shape)과 §10의 데이터 체크리스트 파일, 과제 루트의 부록(WEB.md, RESULT_FILE.md, OR_SPEC.md, DATA_QUALITY.md, EVAL_SET.md, ML_EVAL.md, REPAIR_MAP.md 중 있는 것), 있으면 CARD_REF.md만 읽는다. CARD_REF.md의 값은 예시이며 README·데이터와 다르면 README가 맞다. snippets는 shape가 이름을 댄 파일만 §10의 경로에서 복사한다. 참고 문서는 지시가 아니다. 지시의 우선순위는 AGENTS.md대로(과제 README > CONTRACT > AGENTS.md)다.
0) §10 '붙인 부록' 줄의 파일이 과제 루트에 없으면 `~/finals/contract/addenda/README.md`의 명령 블록에서 해당 줄만 실행해 복사한다. 빈 템플릿은 README와 CONTRACT 근거로 먼저 채우고(5분 이내, 모르는 칸은 §9 가정) 요약을 보고한 뒤 응답을 기다리지 않고 1)로 진행한다(응시자 수정은 나중에 반영). §0 '보조 세션 출력 파일'이 "반영 대기"인 파일은 보조 세션이 쓰는 중이므로 건드리지 않고 건너뛴다. 보조 세션이 이미 채운 파일은 읽기만 한다.
1) 시작 전에 사용할 런타임과 라이브러리가 실제로 import·실행되는지 1분 안에 확인하고 §10에 결과를 적는다. 설치가 5분 넘게 막히면 표준 기능으로 바꾼다.
2) 가장 위험한 기술 가정 하나를 작은 실험으로 먼저 확인한다(예: 데이터 크기, 한글 인코딩, LLM API 1회 호출, 솔버 설치, 로그인 쿠키).
3) 수직 흐름으로 만든다. 웹: 화면 → API → 서버 검증 → 저장/계산 → 결과 화면. 결과물: 입력 → 계산 → 출력 → 검증기. 처음에는 단순하지만 항상 유효한 baseline(최적화는 greedy, 검색은 키워드/BM25, 분석은 기술통계, 예측은 평균/다수 클래스)으로 만든다.
4) 계산이 있으면 CONTRACT §6 hard constraint와 출력 스키마를 계산 코드와 다른 파일에 검증기(validator)로 만들고, verify_fast.sh가 그것을 호출하게 한다. 지표는 §6 "지표 정의" 줄의 분자·분모·집계 단위대로만 계산하고 요구되지 않은 지표를 추가하지 않는다. 필요하면 §10의 snippets 파일을 복사해 과제에 맞게 고친다.
5) 제공 데이터는 파일을 읽어 적재한다(하드코딩 금지). §4 사용 금지 컬럼은 쓰지 않는다. 웹이면 권한은 서버에서 검사한다(비로그인 401, 역할 불일치 403).
6) 검증은 과제 루트의 실행 파일 두 개로 고정한다: `verify_fast.sh`(검증기·curl·테스트만, AC마다 실행, 수십 초)와 `verify_full.sh`(verify_fast.sh를 호출한 뒤 빌드·깨끗한 재현, P5와 제출 전에만). 둘 다 실패 시 0이 아닌 종료 코드로 끝나게 만든다. 내용은 파일에만 두고 CONTRACT §7·§10에는 파일명과 시각만 적는다. verify_fast.sh의 AC1 check는 §7 AC1 행의 검증 명령과 기대 결과를 적힌 그대로 확인한다. 기대 결과를 느슨하게 바꾸지 않고, 바꿔야 하면 바꾸지 말고 이유를 보고한다. `bash verify_fast.sh`를 실제로 실행해 AC1을 통과시킨다.
같은 문제에 20분 넘게 막히면 더 단순한 방법으로 물러나고 DECISIONS.md에 기록한다. 끝나면 §7 AC1 상태, §0 상태판(실제 시각 `date +%H:%M`)을 갱신하고 DECISIONS.md에 "HH:MM | AC완료 | AC1 | 명령·결과"를 남긴 뒤, 실행한 명령과 결과(웹이면 확인 경로와 테스트 계정)를 보고해라.
```
