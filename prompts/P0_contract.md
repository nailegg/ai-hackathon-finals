# P0 · 계약 추출 (코드 금지)

**언제:** T+5~15. `AGENTS.md`, `CONTRACT.md`, `DECISIONS.md`를 과제 루트에 복사한 **뒤** 메인 세션을 시작하고 붙여 넣는다.
**사람:** 이 프롬프트가 도는 동안 Terminal 2에서 런타임 확인과(웹 가능성이 있으면) boilerplate 반입을 한다. 끝나면 `RUNBOOK_330.md` 5절의 1~7번을 순서대로 따른다.

```text
먼저 과제 루트의 AGENTS.md를 읽어라(규칙과 용어). 그다음 과제 README.md와 제공 파일을 읽고 CONTRACT.md를 채워라. README.md가 없고 TASK_SPEC.md가 있으면 그 파일이 과제 명세이며, 아래의 "README"는 모두 TASK_SPEC.md를 뜻한다. 데이터 파일은 헤더·행 수·샘플 5행만 본다(상세 프로파일은 다음 단계). 코드와 다른 파일은 만들지 마라. web/ 디렉터리나 ~/finals/ 아래는 아직 보지 마라(맨 마지막 단계의 카드 색인 한 파일만 예외).

채울 절: §1 요약, §2 제출 계약, §3 채점 가설, §5 역할 또는 인터페이스, §6 핵심 계산, §7 수용 기준, §8 범위 밖, §9 가정, §10 구현 기반 결정. §4는 비워 둔다.
- 모든 항목에 README 근거(절 또는 짧은 인용)를 단다. 근거가 없는 것은 §9 가정 레지스터에 A번호로 등록한다.
- §2: 채점자가 가장 먼저 볼 산출물 하나와 한 줄 실행 명령을 반드시 정한다. sample 출력 파일이 있으면 그 형식이 계약이다.
- §3: 심사는 종료 후 2시간 안에 끝난다. 자동 지표 / 명령·화면 확인 / 과정 평가 / 서술형 중 무엇이 주인지 README 문구와 제공 파일로 추정하고 우선순위를 적는다.
- §7: 채점자가 브라우저나 명령으로 확인할 수 있는 문장으로 5~8개, 가장 중요한 사용자 여정부터. 각 AC에 필수 여부(채점에 직접 연결되면 예), 검증 명령 후보, 기대 결과를 적는다. 상태는 모두 "미착수".
- §10 주 shape 제안은 다음 중 하나로 고르고 근거를 적는다: web_fullstack(로그인·역할·저장·화면) / or_optimization(배정·스케줄·경로, 결과 파일 또는 웹 안의 계산) / data_analysis_ml(예측·이상탐지·보고서) / rag_agent(문서 검색·질의응답·승인) / etl_pipeline(변환·정제·집계) / simulation_whatif(시나리오 재생·KPI 비교) / code_repair(기존 코드와 실패 테스트) / unknown. 혼합이면 채점자가 확인할 산출물을 결정하는 쪽을 주 shape로, 그 안의 계산·검색·추출은 §10 계산 shape 줄에 하나만 적는다(어느 조합이든 가능). 어느 정의에도 1:1로 맞지 않으면 unknown 하나만 적고 계산 shape는 비운다.
- §10 Web Boilerplate 사용은 다음을 모두 만족할 때만 "예": 브라우저로 확인하는 웹 서비스 / 로그인·역할·데이터 저장 중 둘 이상 필요 / 언어·프레임워크·스타터 지정 없음 / 기존 코드 수리 아님 / node 20 이상.
- §10 런타임 LLM API 제공 여부와 근거를 적는다. 없으면 LLM 없는 방식으로 §6·§7을 쓴다.
- 부록이 필요하면 §10 '붙인 부록' 줄에 과제 루트 파일명으로 적는다(WEB.md / RESULT_FILE.md / OR_SPEC.md / EVAL_SET.md / ML_EVAL.md / REPAIR_MAP.md / DATA_QUALITY.md). 복사는 P2에서 한다.
- 시각은 `date +%H:%M`으로 확인한 실제 시각으로 적는다. §0의 시작/점심/종료 시각 줄은 내가 적었거나 적을 것이다.
- 위를 모두 쓴 뒤 **맨 마지막에** ~/finals/domain/CARD_INDEX.md 한 파일만 읽어라(~/finals/의 다른 파일과 카드 원본은 읽지 마라). 그 파일의 "고르는 규칙"대로 §10 '참고 카드 제안' 줄에 "S0n" 또는 "없음"과 차이 3개(입력 단위·산출물·채점 방식)를 한 줄로 적는다. 색인을 읽은 뒤에는 CONTRACT의 다른 줄을 고치지 마라. 파일이 없으면 "없음(색인 없음)"으로 적는다. CARD_REF.md는 만들지 마라.
끝나면 §1·§3·§7 요약, §10 주 shape 제안과 카드 제안 한 줄씩, 그리고 결과를 바꾸는 모호함(§9 중 되돌릴 비용 "높음")만 보고해라. 그 밖의 가정은 등록만 하고 진행한다.
```

**사람 검토:** `RUNBOOK_330.md` 5절의 1~7번을 순서대로 따른다. 검토 항목은 런북에만 둔다.
