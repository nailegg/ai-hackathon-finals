# P4 · 체크포인트와 재개

접속이 끊기면 AI 대화 기록이 사라질 수 있다(2차 예선 실제 사례). 모든 상태는 파일에 있어야 한다.

## 중단 전 (점심 직전, 자리 비우기 전, 모델 교체 전)
```text
기능 작업을 멈추고 상태를 파일에 남겨라. §0 상태판을 지금 시각(`date +%H:%M`)으로 갱신하고(진행 중 AC, 마지막 검증 결과, 다음 행동 1개, 실행 중 서버·명령), DECISIONS.md에 "HH:MM | 체크포인트 | 진행 중 작업과 다음 행동" 한 줄을 쓴다. 최근 수정 파일 목록(ls -lt | head)을 보고해라. 서버는 끄지 마라.
```
**사람:** 서버 터미널은 그대로 둔다. 제출 플랫폼 세션이 만료될 수 있으니 복귀 후 먼저 접속을 확인한다.

## 재개 (점심 후, 재접속 후, 새 세션에서)
```text
AGENTS.md를 읽고, CONTRACT.md는 §0 상태판 → §7 수용 기준 → §10 순서로 읽어라. DECISIONS.md 마지막 10줄과 작업 폴더의 최근 수정 파일(ls -lt | head -20)을 확인한 뒤, §0의 "다음 행동"부터 이어서 해라. 통과한 AC를 다시 만들지 마라. 먼저 `bash verify_fast.sh`를 한 번 실행해 현재 상태가 §7과 일치하는지 확인하고 다르면 §7을 사실대로 고친 뒤 진행해라. §10의 참고 문서(shape, CARD_REF, 데이터 체크리스트)는 다시 통독하지 말고 지금 AC에 필요한 절만 grep으로 본다. 서버가 필요한데 3000번이 응답하지 않을 때만 띄운다.
```

## 접속 장애가 반복될 때 (사람)
- 같은 요청을 연타하지 않는다. 플랫폼 상태 공지와 운영진 안내를 확인하고 장애 시각·문구를 메모한다(DECISIONS에도 한 줄).
- 재접속마다 재개 프롬프트를 쓴다. 세션이 바뀌어도 파일이 상태를 가지고 있으므로 손실은 "마지막 체크포인트 이후 작업"뿐이다. 그래서 AC마다 §0을 갱신한다.
- 모델 capacity 오류는 `checklists/recovery.md`.
