# P6 · 제출 문서

**언제:** T+285~305. 감사 결과가 나온 직후.
**사람:** 같은 시간에 서술형 메모를 쓴다(아래). T+305부터 제출 절차(`checklists/submission.md`).

```text
과제 루트에 제출 문서를 작성해라. 과제 README가 형식이나 파일명을 지정하면 그것을 따르고, 없으면 SUBMISSION.md로 쓴다. 실제로 실행해 본 명령만 적는다.
순서: 1) 한 줄 요약과 실행 환경(런타임 버전) 2) 설치와 한 줄 실행 명령(§2), 웹이면 서버 실행·접속 경로·역할별 테스트 계정 3) 산출물 목록과 위치 4) 방법: 입력 → 처리 → 출력, 핵심 계산과 baseline, 독립 검증 방법 5) 결과 지표와 verify 결과(§7 상태표 그대로) 6) 주요 가정(§9에서 결과에 영향 있는 것)과 결정(DECISIONS 요약) 7) 한계와 미완료 항목(사실대로) 8) 개선 방향 3개.
분석·보고서 과제면 질문 → 데이터 → 방법 → 결과 → 한계 순서로 쓴다. 과장하지 말고 미검증은 미검증으로 적어라. 끝나면 §0을 "제출 문서 완료"로 갱신하고 DECISIONS.md에 한 줄 남겨라.
```

**서술형 메모 (사람, AI 없이 말할 수 있어야 하는 것):**
1. 왜 이 형태·스택·baseline을 골랐나 (§10, §6)
2. 핵심 알고리즘과 trade-off, 버린 대안 (DECISIONS)
3. 어떻게 검증했고 무엇이 남았나 (§7, 감사 결과)
4. 가정 중 결과를 바꿀 수 있는 것 (§9)
