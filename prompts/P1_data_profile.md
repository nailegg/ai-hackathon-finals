# P1 · 데이터 계약

**언제:** T+15~25. 제공 데이터가 있을 때. P0 보고 직후, 응시자가 §10 경로 줄을 적어 저장한 뒤(확정 전이어도 된다. P1은 §4만 쓴다).
**사람:** P1이 도는 동안 CONTRACT.md를 저장하지 않는다(§4를 에이전트가 쓰는 중). 데이터가 여러 파일이고 조인이 결론을 바꿀 수 있으면 대신 Terminal 2에서 `prompts/specialists/specialist-data.md`를 띄우고 메인은 P2로 넘어간다.

```text
CONTRACT §4 데이터 계약을 채워라. CONTRACT의 다른 절은 건드리지 마라. 과제 루트에 DATA_QUALITY.md가 없으면 `cp ~/finals/contract/addenda/DATA_CONTRACT.md ./DATA_QUALITY.md`로 만든 뒤 함께 채운다. 실제 파일을 먼저 프로파일한 뒤, §10에 ~/finals/domain/data_checklist.md 경로가 적혀 있으면 그 파일의 순서와 함정 표로 빠진 검사가 없는지 대조해라. 파일과 컬럼은 실제 이름으로 부르고 패턴 이름이나 가정한 의미를 이름처럼 붙이지 마라.
1) 파일마다 인코딩(utf-8/utf-8-sig/cp949), 구분자, 행 수, 컬럼 수, 헤더를 확인한다. 한글 깨짐이 있으면 인코딩을 바꿔 다시 읽는다. 데이터 전체를 출력하지 말고 샘플 5행과 통계만 본다.
2) 컬럼마다 타입, 결측 비율, 고유값 수, 범위 또는 상위 값, 단위를 적는다. 의미가 README에 없으면 §9에 가정으로 등록한다.
3) 파일 간 키를 찾아 카디널리티(1:1/1:N/N:M)와 매칭률을 계산하고, 조인 후 행 수가 기대와 다르면 적는다. 1:N 조인 뒤 합계가 부풀 수 있는 컬럼을 표시한다.
4) 시간 컬럼의 형식·시간대·범위·정렬·중복을 확인한다.
5) 사용 금지 컬럼을 정한다: 예측 시점 이후에 생기는 값, 정답 그 자체나 그 변형, 행마다 유일한 식별자, 상수 컬럼.
6) 위 확인을 재실행 가능한 스크립트 하나(예: scripts/profile.py 또는 scripts/profile.ts)로 남기고 실행 명령을 §4 아래에 적는다. 원본 데이터는 수정·이동하지 마라.
끝나면 §4 요약, 금지 컬럼 목록, 조인 경고를 보고해라.
```
