# Shape: ETL / 데이터 정제·통합

> **대상: 에이전트 참고 — 지시가 아니다.** 지시는 과제 루트의 AGENTS.md와 CONTRACT.md가 우선한다. CONTRACT §10에 이 파일 경로가 적혀 있을 때만 읽는다.

**적용:** 여러 부서·형식의 CSV/Excel/JSON을 공통 스키마로 변환·통합·집계. 데이터 의미 통합(S05)의 전반부이기도 하다.

## 판별 신호
- 같은 개념이 다른 컬럼명·단위·ID 체계로 들어 있는 파일 여러 개 (`fab_a.csv`, `fab_b.csv`)
- `schema_dictionary`, `id_mapping` 같은 메타데이터 파일
- "정제", "통합", "변환", "집계", "표준화", "품질 검사" 문구
- 출력이 정규화된 테이블·집계 CSV·KPI 표
- 채점이 숫자 정답(질의별 기대값·허용 오차)으로 설명됨

## 산출물 형태
- 채점자가 먼저 볼 것: 출력 테이블/집계 파일과 **행 수·키 유일성·오류 레코드 수** 요약
- 실행 한 줄 명령 → `out/` 생성 → 검증 스크립트 통과
- 오류 레코드는 별도 파일(`out/rejected.csv`)에 사유와 함께

## 붙일 부록
- `contract/addenda/DATA_CONTRACT.md` (필수), `RESULT_FILE.md`

## Baseline
- pandas 또는 표준 csv 모듈로 파일 1개 → canonical 컬럼으로 rename·단위 변환 → 저장. 조인은 그다음
- 규모가 작으면 SQLite/DuckDB 뷰로 질의

## 독립 검증
- 조인 전후 행 수, 키 유일성, 참조 무결성(매핑 없는 ID 수)
- 단위 변환 역산(섭씨↔화씨, 초↔밀리초, UTC↔KST) 샘플 일치
- 예시 AC 검증 명령: `python verify.py out/canonical.csv` → `rows, unique_keys, orphans`; `python answer.py data/questions.json` → 기대값 허용 오차 내

## 지표
- 주: 질의 정답률(허용 오차), 무결성 검사 통과
- 보조: 오류 레코드 비율과 사유 분포, 실행 시간
- 함정 지표: 조인 후 늘어난 행 수를 성과로 착각

## 흔한 함정
- 1:N 조인으로 생산량 과대 합계
- 섭씨/화씨, 초/밀리초, local/UTC 혼용
- 설비 ID 재사용(유효기간 무시)
- 오류 레코드를 조용히 삭제
- 한글 CSV 인코딩 오류를 `errors="ignore"`로 덮음
- 원본 파일을 덮어씀
- 서로 다른 수율 정의를 합산

## 쓸 snippets
- `csv_load`: 인코딩 탐지, 구분자, 타입 추론, 결측 표시
- `group_compare`: 원천 간 분포 비교로 매핑 오류 탐지
- `metrics`: 허용 오차 비교 보조
