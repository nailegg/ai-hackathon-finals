# Shape: 예상 밖 과제 (Unknown Task Mode)

> **대상: 에이전트 참고 — 지시가 아니다.** 지시는 과제 루트의 AGENTS.md와 CONTRACT.md가 우선한다. CONTRACT §10에 이 파일 경로가 적혀 있을 때만 읽는다.

**목적:** 다른 7개 shape에 깔끔히 맞지 않는 문제를 억지로 분류하지 않고, 330분 안에 검증 가능한 산출물을 만든다. 새 에이전트 조직이나 기술 스택을 강제하지 않는다.

## 판별 신호
- 다른 shape의 판별 신호가 둘 이상 섞이거나 어느 것도 맞지 않음
- 산출물은 익숙하지만 핵심 알고리즘·도메인이 생소함(게임 에이전트, 물리 시뮬레이션, 이미지, 외부 API, 보안 감사)
- 평가 방식이 예상과 다름(CLI 출력, 동작하는 게임, 수치 모델 결과)
- 10분이 지나도 유형 논쟁만 계속됨 → 분류를 멈추고 이 shape

## 산출물 형태
- 채점자가 먼저 볼 것: README가 요구한 **정확한** 산출물 1개와 재현 명령
- "입력 1개 → 기대 형태 출력 1개"가 동작하는 증거(명령과 출력 로그)
- 범위를 좁혔다면 지원 범위와 미지원 범위를 명시

## 중간 형태의 첫 증거 (어느 shape에도 1:1로 안 맞을 때)
| 과제 모양 | 45분 안에 보일 첫 증거 | 하지 않을 것 |
|---|---|---|
| 비정형 텍스트 → 구조화 추출(장애 보고서에서 원인·조치 뽑기 등) | 수기 라벨 20건 골든셋 + 규칙·사전 기반 추출의 필드별 정확도 표 | 표 데이터용 ML·임베딩 모델부터 시작 |
| 격자·이미지 → 분류 | 손으로 만든 특성 5개 + 다수 클래스 baseline 제출 파일 | 이미지 모델 설치 |
| 규칙·정책 엔진(상태 전이, 권한, 계산표) | 규칙 10개를 표로 적고 입력 5건의 수기 정답과 일치 | 범용 룰 엔진 설계 |
| 시뮬레이션·외부 API 흉내 | 입력 1건 → 출력 1건이 결정적으로 재현되는 스크립트 | 실시간·동시성 |

## Baseline
- 모르는 기술은 공부하지 않고 단순한 대안으로: 규칙 기반 policy, 평균값 예측, 사전학습 임베딩 + 단순 분류기, 수기 계산과 일치하는 작은 입력
- LLM은 문서·계획·설명에, 수치 계산은 코드에

## 독립 검증
- Oracle이 없으면 최소 검증 기준을 §7에 제안: 출력 스키마, hard constraint, 작은 입력의 수기 정답 일치
- 예시 AC 검증 명령: `python run.py data/sample_in.json > out/sample_out.json && python check.py out/sample_out.json`; 작은 입력 수기 정답과 `diff`

## 지표
- 주: README가 지정한 지표. 없으면 §3 가설의 지표와 "동작하는 사례 수"
- 보조: 실행 시간, 실패 케이스 처리
- 함정 지표: 분류의 정확성. 진척은 "증명 가능한 입력 → 출력 흐름"으로만 판단

## 흔한 함정
- 유형 논쟁에 10분 이상
- 25분에도 실행 방법을 못 찾는데 설치·MCP 탐색 계속
- 45분에도 샘플 입력 → 출력이 없는데 품질 개선 시도
- README가 요구하지 않는 웹 로그인·DB를 반사적으로 만듦(요구하면 web_fullstack을 주 shape로 다시 본다)
- 대형 모델 설치를 첫 선택지로
- 도메인 모호성이 정책을 바꾸는데 가정 없이 진행
