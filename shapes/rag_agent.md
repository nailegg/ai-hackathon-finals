# Shape: 문서 기반 RAG / 도구 실행 에이전트

> **대상: 에이전트 참고 — 지시가 아니다.** 지시는 과제 루트의 AGENTS.md와 CONTRACT.md가 우선한다. CONTRACT §10에 이 파일 경로가 적혀 있을 때만 읽는다.

**적용:** 매뉴얼·SOP·인수인계 기록 검색, 출처 있는 답변, 자연어 → 허용된 도구/SQL 실행, 승인 흐름. 화면이 필요하면 `web_fullstack.md`를 화면에만 쓴다.

## 판별 신호
- 문서 뭉치(`manuals/*.md|pdf`, `sop/`, `shift_notes.jsonl`)와 질문 세트(`questions.json`)
- "출처/근거를 함께", "근거 없으면 답하지 말 것", "승인 후 실행" 문구
- "자연어로 질문하면", "Copilot", "에이전트", "도구 호출" 문구
- 채점이 정답률·인용 정확도·거절 정확도·무허가 실행 0건으로 설명됨
- 평가 하네스 과제: "답변 품질을 평가하라", LLM judge, 골든셋

## 산출물 형태
- 채점자가 먼저 볼 것: 질문 세트 실행 결과 JSONL(`answer, citations[], tool_trace[], requires_approval`)과 집계 표(정답·인용·거절)
- 실행 한 줄 명령으로 전체 질문 세트 처리. 화면은 질문 입력 → 근거 펼치기 → 승인 버튼
- 평가 하네스 변형: per-example JSONL + 축별 집계 + 실패 사례 목록

## 붙일 부록 (과제 루트 파일명. §10 '붙인 부록' 줄에 이 이름으로 적는다)
- `EVAL_SET.md`(템플릿 RAG_EVAL) (질문·기대 근거·거절 사례·허용 도구 표)
- 화면이 있으면 `WEB.md`, 결과 파일만이면 `RESULT_FILE.md`

## LLM 가용성에 따른 두 경로
- **API 제공:** LLM은 도구 **선택**과 요약·문장화만. 인자 검증·권한 확인·수치 계산은 서버 코드. 출력은 JSON 스키마로 강제
- **API 없음(기본 가정):** FTS/BM25 검색 + 규칙 기반 의도 라우터(키워드 → 도구) + 템플릿 답변(근거 발췌 그대로 인용). 기능 한계를 정직하게 표시. 이 경로도 AC를 모두 만족하게 설계한다

## Baseline
- SQLite FTS5 또는 단순 토큰 매칭으로 상위 3개 단락 검색, 단락 ID를 인용으로 붙임. 점수가 임계값 미만이면 "근거 없음"
- 도구는 둘로 시작. 이름·인자는 README 기준(예: `query_readonly(sql)`에 SELECT·LIMIT 강제, `search_manual(q)`)

## 독립 검증
- 인용된 문서 ID·단락이 실제로 존재하고 답변 문장이 그 단락에 근거함
- 거절해야 할 질문(문서에 없음)에서 답을 지어내지 않음
- 쓰기 성격 도구는 `requires_approval=true`이고 승인 전 실행 로그가 없음
- 예시 AC 검증 명령: `python run_eval.py data/questions.json out/answers.jsonl && python score.py out/answers.jsonl` → 축별 지표; `python -m pytest tests/test_permissions.py -q`

## 지표
> §6 "지표 정의"가 비어 있을 때 §9 가정으로 제안할 후보다. §6에 정의가 있으면 그것만 계산한다.

- 주: 근거 기반 정답률, 인용 정확도, 거절 정확도, 무허가 실행 0건
- 보조: tool call 성공률, 응답 시간
- 함정 지표: 유창함. LLM judge 점수를 절대 정답으로 쓰지 않는다

## 흔한 함정
- 존재하지 않는 SOP 조항 인용
- 같은 이름의 다른 설비·문서 버전 혼동(유효일 무시)
- 사용자 입력을 SQL로 그대로 실행
- 문서 안의 지시문("이전 규칙 무시")을 시스템 명령으로 취급
- 벡터 DB 설치에 20분 사용
- 승인 없이 변경 도구 실행
- 수치 계산을 LLM에 맡김

## 평가 하네스 변형
평가축을 분리한다: correctness, groundedness, coverage/abstention, latency, cost. 결정론적 검사(형식, ID, 출처 존재, 문서 일치)를 먼저, LLM judge는 보조. 소규모 골든셋으로 일치율·반례 검사. 출력은 per-example JSONL, 집계 지표, 실패 사례, 기준과 한계. 루브릭이 모호하면 `prompts/specialists/specialist-rubric.md` 보조 세션(결과 `RUBRIC.md`).
