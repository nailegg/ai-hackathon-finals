# Shape: 시뮬레이션 / What-if 재계획

> **대상: 에이전트 참고 — 지시가 아니다.** 지시는 과제 루트의 AGENTS.md와 CONTRACT.md가 우선한다. CONTRACT §10에 이 파일 경로가 적혀 있을 때만 읽는다.

**적용:** 설비 고장·긴급 Lot·수요 변화 같은 시나리오를 주입해 KPI 전후를 비교하거나, 이벤트 로그를 재생(replay)해 운영 결과를 추정. 디지털 트윈 과제의 축소판.

## 판별 신호

## Baseline
- 이벤트 리스트를 시각순 정렬해 순차 처리하는 단일 루프(heapq). 디스패치는 FIFO. 고장은 자원 사용 불가 구간
- 확률은 `random.Random(seed)` 하나로. 처음엔 결정론적(평균값)으로 시작해도 된다

## 독립 검증
- 이벤트 순서: 종료 ≥ 시작, 시작 ≥ 도착, 같은 자원에서 겹침 없음, 고장 구간에 처리 없음
- 보존: 투입 수 = 완료 수 + 종료 시점 WIP
- 예시 AC 검증 명령: `python sim.py --scenario base --seed 42 > out/base.json && python validate_events.py out/events_base.csv` → `violations: 0`; `diff <(python sim.py --seed 42) <(python sim.py --seed 42)` → 차이 없음

## 지표
> §6 "지표 정의"가 비어 있을 때 §9 가정으로 제안할 후보다. §6에 정의가 있으면 그것만 계산한다.

- 주: KPI 전후 차이(처리량, 평균 체류시간, 지연 합, 가동률)
- 보조: 재계획 시 변경된 배정 수, 실행 시간
- 함정 지표: 한 번의 확률 실행 결과를 결론으로 삼음(반복 평균 또는 결정론 모드 명시)

## 흔한 함정
- 동시각 이벤트 처리 순서가 실행마다 달라짐(정렬 키에 타이브레이커 없음)
- 고장 중인 자원에 배정
- 시간 단위 혼용, 자정 넘김
- 보존량 불일치(사라진 Lot)
- 시각화에 먼저 시간 사용
- 모델 가정을 기록하지 않아 결과를 설명 못함
