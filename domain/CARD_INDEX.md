# 카드 색인 (P0 마지막 단계)

> **대상: 에이전트.** P0에서 CONTRACT의 다른 줄을 모두 쓴 **뒤에** 이 파일 하나만 읽는다. `scenarios/` 아래 카드 원본은 읽지 않는다. 이 색인은 "이 과제와 닮은 연습 카드가 있는가"를 고르는 데만 쓴다. 여기 적힌 말로 CONTRACT의 다른 절을 고치지 않는다. 카드는 출제 **가설**이고, 닮은 카드가 없는 것이 정상이다.

| 카드 | 다루는 일 | 입력 형식 | 산출물 |
|---|---|---|---|
| S01 | 공정 이상 Lot·설비 탐지와 원인 후보 제시 | 표(센서 시계열·공정 이력·검사) + 텍스트(사고 로그·절차 문서) | 분석 화면 또는 보고서 |
| S02 | 문서 근거 질의응답과 고위험 조치 승인 | 텍스트(매뉴얼·교대 기록·사고 이력) + 표 | 질의·승인 화면 |
| S03 | 검사되지 않은 Wafer의 품질 값 예측 | 표(센서·일부 계측값) | 예측 결과 파일(제출 샘플 형식) |
| S04 | Lot-설비 스케줄 작성과 장애 시 재계획 | 표(Lot·적격 설비·가용 시간·납기) | 일정 화면 또는 결과 파일 |
| S05 | 컬럼명·단위·ID 체계가 다른 데이터의 통합과 자연어 질의 | 표(출처마다 스키마가 다름) | 통합 테이블 + 질의 응답 |
| S06 | 예산 안에서 다음 실험 조건 추천 | 표(실험 결과·조건 범위·단가) | 추천 결과 파일·보고서 |
| S07 | 설비 정비 일정·부품 재고 계획과 담당자 승인 | 표(정비 주기·근무표·재고·생산 계획) | 역할이 있는 웹 화면 |
| S08 | 반송 요청의 차량 배차와 긴급 요청 재배차 | 표(요청·차량·이동 시간 행렬) | 배차 화면 |
| S09 | 테스트 저수율 Lot 탐지와 요인별 집중도 분석 | 표(Bin 결과·테스터·프로그램·제품) | 분석 화면 |
| S10 | 작업허가 신청·다단계 승인·감사 로그 | 화면 입력(신청서) + 표(규칙) | 역할이 있는 CRUD 화면(상태 흐름) |
| S11 | 웨이퍼맵 불량 패턴 분류와 추이 보고 | 격자·이미지(Die 단위 양/불) | 분류 결과 파일 |

## 고르는 규칙

1. 비교 대상은 방금 쓴 CONTRACT다. 입력 형식은 제공 파일의 종류(표·텍스트·이미지·코드), 산출물은 §2 "채점자가 가장 먼저 볼 것"이다.
2. **입력 형식과 산출물이 둘 다 같은 카드만 후보다.** 주제어(스케줄, 수율, 승인 등)만 같은 카드는 후보가 아니다.
3. 후보가 둘 이상이면 카드의 "다루는 일"이 CONTRACT §1 과제 요약과 같은 쪽 하나만 남긴다. 그래도 둘이 남으면 "없음"이다.
4. 남은 후보와 과제의 차이를 셋으로 적는다: 입력 단위, 산출물, 채점 방식(§3). 채점 방식은 지표의 종류까지 본다(회귀 오차, 분류·순위 지표, 제약 위반 수, 정답 일치). 셋 중 하나라도 §7 AC1이나 §3 주 채점 방식을 바꾸는 차이면 "없음"이다.
5. 확신이 없으면 "없음"이다. 잘못 고른 카드는 없는 것보다 해롭다.

## 적는 곳과 형식

CONTRACT §10 "참고 카드 제안" 줄에 한 줄로 적는다.

- 후보가 있을 때: `S07 | 입력 단위: <과제> vs <카드> | 산출물: <과제> vs <카드> | 채점: <과제> vs <카드>`
- 없을 때: `없음 | <가장 가까웠던 카드와 탈락 이유 한 구절, 또는 "해당 없음">`

발췌 파일(`CARD_REF.md`)은 응시자가 만든다. 직접 만들지 않는다.
