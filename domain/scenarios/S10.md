## 가상 출제문
"정비·공사 작업의 허가 신청, 위험성평가, 승인, 작업 중 점검, 종료를 관리하는 시스템을 만드시오. 작업 유형별 필수 점검 항목과 승인 단계를 지키고, 고위험 작업은 2단계 승인이 필요하며, 모든 변경은 감사 로그에 남겨야 한다. 신청 내용으로 위험 등급을 자동 산정하고 필요한 점검 항목을 제안하시오."

## Baseline
1. 상태 머신은 README가 정한 상태명과 단계 수로(예: `DRAFT → SUBMITTED → APPROVED_L1 → APPROVED_L2(고위험만) → ACTIVE → CLOSED`, `REJECTED`). 전이 함수 하나에 역할·상태 검사 집중.
2. 위험 등급 = hazard_matrix[likelihood][severity], 작업 유형 base_risk와 max.
3. 필수 점검 항목 = work_types.required_checks + 등급별 추가 항목. 모두 체크돼야 ACTIVE.
4. 감사 로그: 모든 전이·수정에 `who, when, from, to, reason`.

## 독립 검증
- 역할 불일치 전이 403(감독자가 2차 승인 시도, 자기 승인).
- 필수 점검 미완료 상태에서 ACTIVE 불가.
- 허가 기간 겹치는 동일 설비·구역의 충돌 작업 경고(LOTO 등).
- smoke: 비로그인 401, 신청자가 타인 신청 수정 403.

## KPI
규칙 위반 전이 0건, 감사 로그 완전성(전이 수 = 로그 수), 처리 시간(신청→승인), 고위험 2단계 승인 준수 100%.

## 함정
화면에서 버튼만 숨기고 서버 검사 없음, 상태 전이가 여러 API에 흩어짐, 감사 로그 누락, 위험 등급표 축 혼동(likelihood/severity), 시간대.

## 화면 3개
1. 허가 목록(상태·등급·기간 필터, 내 할 일 강조).
2. 신청·상세: 위험 등급 자동 산정, 점검 항목 체크, 승인/반려 버튼(역할별).
3. 감사 로그 + 설비·구역 충돌 캘린더.
