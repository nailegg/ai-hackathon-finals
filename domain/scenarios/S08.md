"반송 요청(출발 포트, 도착 포트, 요청 시각, 우선순위), 차량(위치, 용량, 배터리), 포트 간 이동 시간 행렬이 주어진다. 대기 시간과 총 이동 거리를 줄이는 배차 계획을 만들고, 운영자가 긴급 요청을 추가하면 재배차하는 서비스를 만드시오."

## Baseline
1. 거리 행렬 로드(비대칭 유지, 누락 쌍은 오류). 시간을 초 정수로.
2. `greedy_assign`: 우선순위·due 순으로 요청 정렬, 각 요청에 "가장 빨리 도착 가능한 차량"(현재 위치→출발 포트 이동 포함) 배정, 차량 위치·가용 시각 갱신.
3. 용량 > 1이면 같은 방향 요청 묶기(간단 규칙), 배터리 임계 이하 차량 제외.
4. 개선: 두 요청 교환(swap) local search, 시간 제한.

## 독립 검증 (`validate_schedule` 변형)
- 차량별 작업 시간 겹침 없음, 도착 가능 시각 ≥ 이전 작업 종료 + 이동.
- 용량 초과 0, 모든 요청 배정 또는 미배정 사유.
- pickup ≥ request_time, 거리 행렬에 없는 이동 사용 0.

## KPI
평균·최대 대기 시간(pickup − request), 총 이동 시간, due 초과 건수, 차량 가동 균형, 재배차 시 변경 건수.

## 함정
비대칭 행렬을 대칭으로 가정, 공차 이동(차량→출발지) 누락, 시각 4개 순서 위반, 긴급 요청이 기존 배정 전부를 뒤집음(변경 최소화 목표 필요).

## 화면 3개
1. 배차 실행 + KPI 카드 + 차량별 작업 순서 표.
2. 포트 좌표 위 경로 지도(SVG 선) 또는 차량 타임라인.
3. 긴급 요청 입력 → 재배차 → 변경 diff.
