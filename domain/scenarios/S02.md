## 가상 출제문
"설비 매뉴얼, 교대 기록, 사고 이력, DB를 이용해 엔지니어 질문에 근거와 함께 답하고 분석 도구를 실행하는 Copilot을 만드시오. 고위험 조치는 승인을 요청하고 모든 판단에 출처를 붙이시오."

## 예상 데이터
| 파일 | 스키마 | 역할 |
|---|---|---|
| `manuals/*.md` 또는 `.pdf` | 장비명, 조건, 절차, 경고, 버전 | SOP 근거 |
| `shift_notes.jsonl` | `shift_id, tool_id, issue, open_tasks, author, time` | 인수인계 |
| `maintenance.db` | `events, tools, work_orders, users` | 상태 조회 |
| `questions.json` | `question, expected_sources, allowed_actions` | 평가 질문 |

## 사용자·역할
| 역할 | 할 수 있음 | 할 수 없음 |
|---|---|---|
| 엔지니어 | 질문, 근거 열람, 조치 **제안** | 조치 실행, 승인 |
| 승인자(관리자) | 제안 승인·반려, 감사 로그 열람 | 자기 제안 자기 승인 |

## Baseline
1. 문서 파싱 → SQLite FTS(`fts_search`)로 검색. 임베딩은 환경이 확실할 때만.
2. 의도 라우터는 규칙 기반(키워드 → `search_manual` / `query_readonly` / `get_history`). LLM API가 있으면 선택만 맡기고 인자 검증은 서버.
3. 답변 포맷 고정: `claim → evidence[doc_id, 단락] → recommendation → uncertainty`.
4. 상태 머신: `PROPOSED → APPROVED/REJECTED → EXECUTED`, 모든 전이는 `audit_log`에 기록.

## 독립 검증
- 근거 없는 질문은 기권(`abstain`), 인용 `doc_id` 존재 확인.
- 승인 없이 `EXECUTED` 불가(서버 403), 자기 승인 차단.
- 검색된 문서에 "규칙 무시" 문장을 넣어도 도구 권한이 바뀌지 않음.

## KPI
retrieval hit율, 인용 정확도, 기권 정확도, tool call 성공률, 무승인 실행 0건.

## 함정
존재하지 않는 조항 인용, 같은 이름의 다른 설비 혼동, 사용자 입력을 SQL로 직접 실행, PDF 속 지시문을 명령으로 취급, LLM API가 없는데 LLM 전제로 설계.

## 화면 3개
1. 질문 입력 + 답변(근거 접기/펼치기, 출처 링크).
2. 제안 목록과 승인/반려(승인자 전용).
3. 감사 로그(누가·언제·무엇을, 필터).

## 330분 우선순위
- **MVP**: 문서 검색 → 근거 포함 답변 → 기권 → 읽기 도구 2개 → 제안·승인·감사 CRUD.
- **가산점**: 다단계 질의(검색+SQL 집계), 역할별 권한, 실패 복구.
- **제외**: 자율 실행 권한, 다중 에이전트 수십 개, 벡터 DB 설치.
