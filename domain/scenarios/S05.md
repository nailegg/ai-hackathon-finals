## 가상 출제문
"부서마다 다른 컬럼명·단위·ID 체계의 설비·생산·품질 데이터를 의미적으로 연결하고, 현장 직원이 자연어로 질문하면 계산 근거와 함께 정답을 반환하는 시스템을 만드시오."

## 예상 데이터
| 파일 | 스키마 | 역할 |
|---|---|---|
| `fab_a.csv` | `EQP_NO, LOT_NO, START_TS, GOOD_CNT` | 원천 A |
| `fab_b.csv` | `machine_id, batch_id, start_utc, pass_units` | 원천 B |
| `schema_dictionary.json` | `source, column, canonical_name, unit` | 매핑 근거 |
| `id_mapping.csv` | `local_id, global_tool_id, valid_from, valid_to` | ID 매핑(기간 유효) |
| `questions.json` | `question, expected_value, tolerance` | 정답 질의 |

## 사용자·역할 (웹이면)
현장 직원: 질문·결과·근거 열람. 데이터 관리자: 매핑 사전 수정, 질의 템플릿 관리.

## Baseline
1. canonical 스키마 정의(`tool_id, lot_id, start_at(UTC), good_qty`) → 각 원천을 view로 변환(단위·시간대·ID 매핑, 유효기간 조인).
2. 조인 무결성: 매핑 안 된 ID 목록, 1:N 증가 탐지.
3. KPI 질의 5개를 템플릿으로(읽기 전용 SELECT, LIMIT). 자연어는 키워드 → 템플릿 매칭부터.
4. 응답에 실행 SQL·행 수·사용한 사전 항목을 근거로 첨부.

## 독립 검증
- `questions.json` 정답과 tolerance 내 일치.
- 변환 전후 총량 보존(단위 변환 제외), 매핑 누락 0 또는 목록화.
- SELECT 외 문장 차단, 원본 테이블 쓰기 불가.

## KPI
정답 질의 정확률, 매핑 커버리지, 조인 행 증가 탐지, 응답 시간.

## 함정
℃/℉, 초/ms, local/UTC 혼용; 설비 ID 재사용(유효기간 무시); 1:N 조인 후 생산량 과대합계; 수율 정의가 원천마다 다름; 임의 SQL 실행.

## 화면 3개
1. 질문 입력 → 답(수치) + 근거(SQL, 행 수, 사전 항목).
2. 매핑 사전 표(원천 컬럼 → canonical, 단위) 편집.
3. 데이터 품질: 매핑 누락·중복·행 증가 경고.

## 쓸 snippets와 shape
shape: `etl_pipeline` → `rag_agent`(질의 부분). snippets: `csv_load`, `fts_search`(질문-템플릿 매칭), `metrics`.

## 330분 우선순위
- **MVP**: canonical view + 무결성 검사 + KPI 질의 5개 + 근거 표시.
- **가산점**: 자연어→템플릿 매칭, 모호성 감지, 실행 계획 검증.
- **제외**: 범용 온톨로지, LLM만으로 수치 산출, 무제한 SQL.
