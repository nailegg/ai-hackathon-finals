## 가상 출제문
"테스트 공정의 Lot별 Bin 결과, 테스터·핸들러·프로그램·사이트 정보, 제품 정보가 주어진다. 저수율 Lot을 탐지하고 어떤 요인(테스터, 사이트, 프로그램 버전, 시간대)에서 불량이 집중되는지 분석해 엔지니어에게 조치 우선순위를 제시하는 서비스를 만드시오."

## Baseline
1. Lot 수율 = Bin1 수 / 테스트 수. 제품별 target 대비 저수율 플래그.
2. `group_compare`: 요인별(tester, site, program version, 시간대) Bin 분포 비교, 효과 크기·표본 수. 특정 site_no에 집중되면 하드웨어 의심.
3. 프로그램 버전 변경 시점 전후 수율 비교(변화점).
4. 조치 우선순위 = 영향 수량 × 집중도.

## 독립 검증
- unit 수 합 = Lot qty, Bin 비율 합 = 1.
- 1:N 조인(Lot:unit) 후 Lot 수량 과대합계 없음.
- 저수율 판정이 제품별 기준을 쓰는지(전체 평균 금지).

## KPI
저수율 Lot 탐지 Recall@K, 요인별 효과 크기, 영향 수량, 조기 탐지 시간(프로그램 변경 후 첫 알람까지).

## 함정
Soft/Hard bin 혼용, 사이트 수가 다른 테스터 비교, 재테스트(retest) 중복 행, 프로그램 버전 문자열 정렬 오류, 제품 mix 무시.

## 화면 3개
1. 저수율 Lot 목록(수율, 기준, 주요 fail bin).
2. 요인 분석: 테스터×사이트 히트맵 또는 표, 효과 크기.
3. 조치 기록·우선순위 보드.
