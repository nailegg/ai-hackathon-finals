# 2시간 심사 가설 체크리스트

> **대상: 사람.** P5 감사 보고와 대조한다. 종료 16:00, 발표 18:00이라는 일정에서 나온 가설: 심사자가 오래 볼 수 없으므로 **기계적으로 돌아가는 것, 첫 화면에서 보이는 것, 기록으로 남은 과정**이 점수다. CONTRACT §3 주 가설에 해당하는 절부터 본다.

## A. 자동 지표·hidden test 가설
- [ ] 출력 파일명·경로가 README 지정과 정확히 같다
- [ ] sample 출력이 있으면 컬럼 이름·순서·타입·소수 자리·인코딩·줄바꿈이 일치한다 (`diff` 또는 헤더 비교)
- [ ] 행 수와 ID 집합이 입력과 일치한다 (누락 ID 0, 중복 ID 0)
- [ ] seed 고정, 같은 입력 두 번 실행 결과 동일
- [ ] 미지 ID·빈 파일·결측 컬럼에서 명시적 오류로 끝난다 (죽거나 빈 파일을 쓰지 않는다)
- [ ] hard constraint 위반 0건을 **계산 코드와 분리된** 검증기가 확인했다
- [ ] 실행 시간이 상한 안이다 (측정값을 DECISIONS.md 감사 줄에 적었다)

## B. 명령·화면 확인 가설
> 아래 "제출 문서"는 `SUBMISSION.md`다. 과제 README가 다른 문서를 지정하면 그 문서다. 과제 README 자체는 고치지 않는다.

- [ ] 깨끗한 복사본에서 제출 문서 상단의 명령만으로 처음부터 끝까지 돌아간다
- [ ] 대화형 입력 없음, 절대경로 없음, 환경변수는 `.env.example` 또는 제출 문서에 기본값
- [ ] 웹: 서버 실행 명령, 접속 URL, 역할별 테스트 계정이 제출 문서 상단에 있다
- [ ] 웹: 로그인 → AC1 화면까지 클릭 경로가 제출 문서에 있고 직접 해봤다
- [ ] 웹: 비로그인 401, 역할 불일치 403을 curl로 확인했다
- [ ] 화면에 템플릿·예시 문구·placeholder가 없다 (`check-placeholders.sh` 0건)
- [ ] 산출물 목록이 제출 문서와 실제 폴더에서 일치한다

## C. 과정 평가·AI 심사 가설 (대화 기록·문서)
- [ ] SUBMISSION 상단에 **증거표**가 있다: AC마다 주장 → 확인 명령 → 실제 출력 요약(또는 파일 경로). LLM 심사자가 SUBMISSION.md만 읽어도 검증 가능
- [ ] 주장에 수치가 있으면 그 수치를 낸 명령이 같은 문서에 있다. 근거 없는 형용사("정확한", "최적의")가 없다
- [ ] `CONTRACT.md` §1~§3이 README 근거와 함께 채워져 있다
- [ ] §7 AC마다 검증 명령과 최종 상태가 사실대로 적혀 있다 (실패·미검증 포함)
- [ ] `DECISIONS.md`에 계약 확정 → AC 완료 → 범위 변경 → 감사 → 제출 흐름이 시간순으로 있다
- [ ] 가정이 A번호로 등록돼 있고 결과에 영향 있는 것이 SUBMISSION에 요약돼 있다
- [ ] 개선 전후 수치가 기록돼 있다 (품질 개선을 했다면)

## D. 서술형·발표 가설
- [ ] 설계 선택, 핵심 알고리즘과 trade-off, 검증 방법, 한계를 AI 없이 각 1분 안에 말할 수 있다
- [ ] 버린 대안과 그 이유를 하나 이상 말할 수 있다

## E. 공통 금지
- [ ] git 쓰기 명령 흔적 없음, 원본 데이터 미수정, 외부 전송 없음
- [ ] `node_modules`·빌드 산출물 처리 방침을 제출 방식에 맞게 정했다 (`submission.md`)
