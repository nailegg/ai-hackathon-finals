# 장애 복구: 모델 오류·접속 끊김·세션 교체

> **대상: 사람.** 프롬프트는 `prompts/P4_checkpoint.md`. 장애는 코드 실패가 아니다. 완성도와 장애를 구분해 기록한다.

## 모델 capacity / API 오류 (`Selected model is at capacity` 등)
1. 승인 대기 / 실행 중 / 오류 상태를 구분한다. 같은 요청을 연타하지 않는다.
2. 작업 파일 저장. 가능하면 P4 "중단 전" 프롬프트로 §0을 갱신한다. 안 되면 사람이 `DECISIONS.md`에 `HH:MM | 복구 | 모델 오류 <문구>` 한 줄.
3. 시험이 허용하는 **다른 모델**로 전환한다(제공 환경의 지시를 따른다. 제한된 모델은 쓰지 않는다). 개인 API 키·외부 AI 금지.
4. 반복되면 플랫폼 신고 절차를 쓰고 오류 시각·단계·문구를 기록한다. 타이머가 멈춘다고 가정하지 않는다.
5. 세션을 새로 열면 P4 "재개" 프롬프트. 원인 파악 없이 전체 재생성은 금지.

## 접속 끊김 (2차 예선에서 30초~1분 간격 끊김, 재접속 후 대화 기록 소실 사례)
1. 재접속 후 먼저 서버 터미널과 작업 폴더가 살아 있는지 확인한다(`ls -lt | head`, `curl` 3000번).
2. 에이전트 세션이 사라졌으면 새 세션에서 P4 "재개". 파일이 상태를 가지고 있으므로 손실은 마지막 §0 갱신 이후분이다.
3. 끊김이 잦으면 AC 단위보다 잘게 §0을 갱신하게 한다: "파일을 하나 바꿀 때마다 §0의 다음 행동을 갱신해라."
4. 장애 시각·현상을 `DECISIONS.md`에 남긴다. 운영진 공지와 보상 안내는 사람이 확인한다.
5. 제출 플랫폼 세션도 만료될 수 있다. 복귀 시 제출 화면이 열리는지 먼저 본다.
